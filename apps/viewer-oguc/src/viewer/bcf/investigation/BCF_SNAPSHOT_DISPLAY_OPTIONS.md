# BCF_SNAPSHOT_DISPLAY_OPTIONS.md — where to show snapshots

Investigation/design only, no code changes.

## What already exists (re-verified this task)

The row thumbnail (`IssueTable.tsx`'s "thumb" column, 36×24px `<img>`) is the **only** place any BCF image renders today — confirmed live in an earlier task this session with a real fixture. There is no topic-detail panel anywhere in this app (grepped for `TopicDetail`/`*detail*` component files: none exist; `PropertiesPanel.tsx` has zero BCF awareness beyond a stray unrelated comment). `topic.comments` (already parsed, already adapted, already available on every `BcfTopic`) is likewise never rendered anywhere in the current UI — a **separate but related gap**: this app already throws away comment text today, the same way it currently has no full-size image view.

## "CRAIS viewer reference" — flagging an unknown, not guessing

This task's brief asks for a recommendation "based on CRAIS viewer reference (if applicable)." **I have no knowledge of a tool by this name and found no reference to it anywhere in this repository** (grepped `CRAIS`/`Crais`/`crais` across the whole monorepo: zero matches, including in `README.md`s, `package.json` names, and code comments). I'm not going to guess at what this refers to or fabricate a comparison to a tool I can't verify exists or what it does — flagging this explicitly rather than inventing a plausible-sounding but unverifiable reference. If this names a real internal or client tool, it needs to be pointed to directly (a URL, screenshot, or repo) for a real comparison; absent that, this recommendation is based on this app's own existing UI patterns and well-known, verifiable public BCF viewer conventions (BIMcollab Zoom, Solibri, both of which — per the running processes on this very development machine, `BIMcollab Zoom` and `Solibri` are literally installed and running — use a thumbnail-in-list + full-size-on-select pattern, a widely standard convention, not something unique to one named tool).

## Evaluating the four options the brief poses

**A. Thumbnail in IssueTable row** — already exists, already works, should stay (a list needs *some* at-a-glance visual, and 36×24px is deliberately small to fit a table row without dominating it).

**B. Detail panel, full-size on topic selection** — **recommended as the next real feature to build**, for these concrete reasons specific to this app's existing architecture: `IssueTable.tsx`'s `onSelect` already fires on single-click (currently only used to call `BcfManager.setActiveTopic`, which re-highlights the row and re-glows the 3D pin — see `Phase 3` commit). A detail panel reacting to `state.activeTopic` (already tracked in `BcfManagerState`, already flowing through `BcfPanel.tsx`) requires **no new state plumbing** — it would just be a new consumer of data that already exists and already updates on the exact interaction (single-click) this app already uses for "this is the thing I'm currently looking at." This is the natural, lowest-friction place to also finally surface `topic.comments` (the other already-parsed-but-unrendered data), title/description in full (currently: title shows in the table, `description` doesn't render anywhere for BCF topics at all — a smaller, adjacent gap worth bundling into the same panel rather than fixing images alone and leaving text still invisible).

**C. Overlay the 3D viewport ("view from this angle")** — **not recommended**, and not just as a stylistic preference: a BCF snapshot is a flat, already-composed 2D image (screenshot + optional 2D annotations, per `BCF_MARKUP_SVG.md`) captured at authoring time from a specific camera/FOV/render settings that may not match this app's live renderer at all (different lighting, different visible layers, different loaded models). Overlaying it *on* the live 3D view invites a confusing "is this the current view or the old screenshot" ambiguity. The existing double-click-to-jump-camera feature already provides the "recreate this angle live in 3D" behavior properly (moving the actual camera, not superimposing a flat image) — a viewport overlay would be a redundant, worse way to do the same job the app already does correctly.

**D. Dedicated "BCF Review" section** — **not recommended as a separate route/section**; this app already has a clear precedent for keeping domain content inside its existing docked panel (`DockBottom` → `BcfPanel` → `IssueTable`, all on `/`) rather than spinning up new top-level routes for each feature (the one exception, `/revision`, exists because it's a genuinely different *mode* — a formal compliance workflow, not just "more BCF UI," per that route's own header comment). A detail panel is naturally an expansion of the existing `BcfPanel`/`DockBottom` real estate (e.g., a second column or an expandable row), not a new section.

## Recommendation, stated plainly

Keep A (already works). Build B (detail panel/expanded row reacting to `activeTopic`, full-size image + comments + full description) as the concrete next feature. Skip C. Skip D. See `BCF_SNAPSHOT_RENDERING_PLAN.md` Section 4 for where this would concretely live in the component tree.
